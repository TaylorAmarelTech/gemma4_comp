API client setup

Pull verified knowledge. Never push raw cases.

The hub serves vetted packs and accepts proposals. It does not accept worker case content. The schema rejects free-text case fields at the edge. every endpoint below is read-only or proposal-only.

contains_raw_pii: false on every public response No auto-reporting · no auto-emails
Pull / propose flow

Local system ↔ public hub.

Step 01
List packs

GET /api/packages. see verified + proposed packs and their checksums.

Step 02
Verify manifest

GET /api/packages/{id}/manifest. fetch the signed manifest. Verify sha + signer.

Step 03
Pull bundle

GET /api/packages/{id}/download. download the signed bundle. Verify against manifest.

Step 04
Run locally

Use the bundle as RAG / grep / contact context for your local Duecare run. No callbacks.

List packs

GET /api/packages
curl -fsSL https://duecare-ai.com/api/packages \
  -H "accept: application/json" \
  -H "x-deployment-id: ws-ngo-04"

Pull a corridor pack

GET /api/packages/corridor/qa-np/download
curl -fsSL https://duecare-ai.com/api/packages/corridor/qa-np/download \
  -o corridor-qa-np-3.2.1.tar.zst

# verify the checksum
shasum -a 256 corridor-qa-np-3.2.1.tar.zst
# expected: 7c3f3a8d5e4b8f1c9d2a3b4c5d6e7f8901a2b3c4 …a91d

Submit a public-source update proposal

POST /api/contributions
curl -fsSL https://duecare-ai.com/api/contributions \
  -X POST -H "content-type: application/json" \
  -d '{
    "type": "context",
    "submitter_role": "ngo",
    "organization": "Migrant-Forum Asia",
    "contact_email": "techlead@partner.org",
    "jurisdiction": "qa",
    "corridor": "qa-np",
    "summary": "MoFA wage-protection advisory 2026-04",
    "public_source_url": "https://...gov/advisory/2026-04",
    "consent": true,
    "no_raw_case": true
  }'

Proposals always start as status: "proposed". Curators promote after review. The hub will reject any submission whose payload contains likely worker-case fields (emails, phone numbers, ID-like strings in free text).

Submit anonymized aggregate signal

POST /api/signals/aggregate
{
  "deployment_id": "ws-ngo-04",
  "corridor": "qa-np",
  "sector": "construction",
  "pattern_id": "fee_request",
  "k_anon_floor": 30,
  "period": "2026-W18",
  "count": 42
}

Schema rejects any free-text fields. Edge filter further suppresses submissions that fail the k-anon floor of 30. Opt-in per partner.

Python client

duecare_client.py
from duecare import Client

c = Client(deployment_id="ws-ngo-04")

# list, verify, and pull
packs = c.list_packs(corridor="qa-np", status="verified")
mf    = c.manifest("corridor/qa-np")
assert mf.signer == "curator-04"
bundle = c.pull("corridor/qa-np@3.2.1")
assert bundle.verify()  # sha256 match

# IMPORTANT: never call .submit_case(). it does not exist on the public client
Pre-flight checklist

Before you call any endpoint

  • No worker case content in payload
  • No emails, phones, or IDs in free-text
  • Pin ?version=… for reproducibility
  • Verify checksum after every pull
  • Aggregate signal opt-in respected per turn
Versioning

Semver + signed

All packs follow major.minor.patch. Curator signs every promotion. Manifests reference the previous version's sha for chain auditing.

Endpoints

Read-only by default

  • GET /api/packages
  • GET /api/packages/{id}
  • GET /api/packages/{id}/manifest
  • GET /api/packages/{id}/download
  • POST /api/contributions · proposal only
  • POST /api/signals/aggregate · k≥30
  • POST /api/sentinel/crawl-requests
Auth

Public reads, signed writes

All GET endpoints are public. Proposal/signal POSTs require an issued deployment ID. Curator signing requires a hardware key.
