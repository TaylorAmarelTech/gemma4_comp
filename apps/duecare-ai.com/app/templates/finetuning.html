Phase 3 · methodology

Teaching evidence-grounded behavior without erasing the guardrails.

The benchmark measures how an inference-time harness changes model responses. Fine-tuning asks a separate question: can a model learn stable evidence, uncertainty, and safe-response patterns while the harness continues supplying volatile facts and hard controls? This page explains how we build, vet, organize, and measure that training — and how we guard against a model that memorizes shortcuts instead of understanding.

Status — the training-data publication rung passed; a full trained adapter remains pending. The public measured-response corpus and multiperspective corpus are backed by manifests, checksums, approval records, data cards, loading guides, and public notebooks. Supervised fine-tuning (SFT) trains from inputs paired with reviewed desired answers. Direct Preference Optimization (DPO) learns from preferred and nonpreferred answers. Low-Rank Adaptation (LoRA) trains small adapter weights beside a mostly frozen base model. The current public runs use a central processing unit (CPU) for validation and bounded diagnostics; no graphics processing unit (GPU) fine-tuning ran. No Gemma adapter, merged weights, or independent model-lift result is published yet.
01 · Why train, not just harness

Internalise the stable, tool the volatile.

Training and the harness are not rivals; they target different things. The weights should hold the stable substrate (indicator reasoning, grounded-refusal style, evidence-first shape, and International Labour Organization framing). The harness keeps supplying the volatile facts (current contacts, fee caps, and statutes) so the weights never go stale. We do not assume the two stack — we measure it, in four arms on the same 0–100 benchmark.

armmodelharnesswhat it isolates
Astockoffthe raw baseline
Bstockonthe inference-time harness lift (B−A)
Ctrainedoffinternalisation — training alone (C−A)
Dtrainedonstacking — trained + harness together (D vs B, C)

The headline questions: what fraction of the harness lift (B−A) does training capture on its own (C−A), and does the harness still help a trained model (D−C > 0)?

02 · The training data

Measured differences and fictional scenarios become bounded teaching material.

Each measured-response row retains the prompt, comparable replies, grade evidence, and contamination boundary. The separate multiperspective corpus expands controlled role, time, evidence, and jurisdiction coverage. Incomplete or unvetted rows never enter a training job.

GenerateDistil the lift

High-lift (baseline → harnessed) pairs become SFT targets and DPO preferences (chosen = harnessed, rejected = baseline).

VetQuality + privacy

Target score ≥ threshold, clear lift, personally identifiable information and volatile-contact scrub, citation accuracy, and hard quality gates.

OrganiseAnti-shortcut

Hold out whole typologies, balance, interleave, dedup — so the data can’t be solved by surface shortcuts.

TrainUnsloth Low-Rank Adaptation

Response-only supervised fine-tuning, then optional preference optimization on a commit-pinned Gemma 4 base; optionally export the Generative Pre-trained Transformer Generated Unified Format (GGUF) used by llama.cpp.

EvaluateFour arms

Score the trained model in arms C/D on the same prompts; promote only what generalises.

The public measured-response release contains 791 supervised fine-tuning targets, 791 preference pairs, and 1,582 reward labels. The public multiperspective release contains 25,600 supervised training rows, 25,600 preference-training rows, and 2,048 rows in each held-out split. The measured-response corpus is benchmark-contaminated for independent evaluation; the multiperspective corpus is deterministic synthetic coverage, not real-world effectiveness evidence.

Reasoning-data policy: bundles may include final answers, citations, visible judge rationales, and deliberately authored structures such as indicator → source → safe action. They do not request, scrape, or publish a provider’s private hidden chain-of-thought; hidden-thought markup is a blocking data-quality failure.

03 · Understanding, not shortcuts

The failure mode we design against.

Distillation can teach a model to parrot — map a fee-splitting-shaped prompt to “I cannot” plus an International Labour Organization convention reference without understanding the indicator. A shortcut wins on the training distribution and collapses on anything new. We name the shortcuts, organise the data against them, and — the crux — measure which one we got.

  • Keyword→refusal — trigger words map to a canned refusal regardless of whether the request is actually exploitative.
  • Over-refusal — the model refuses a worker asking about their own rights (a benign query).
  • Citation parroting — it cites the most frequent statute in training, not the one the scenario calls for.
  • Obfuscation blindness — a Base64-encoded, visually confusable, or code-switched version of the same scheme slips through.
How we measure understanding. The headline anti-shortcut metric is the held-out-typology generalisation gap: whole typologies are withheld from training, and we compare internalisation (C−A) on trained typologies vs unseen ones. A large gap = memorisation; a small gap = understanding. Alongside it: perturbation robustness (does the score survive paraphrase / obfuscation?), counterfactual consistency (does the model correctly flip on minimal pairs?), and an over-refusal rate on benign controls. A variant only counts as understanding if it holds up on held-out typologies and under perturbation and on counterfactuals.
04 · The training run

The canonical Unsloth recipe, reproducibly.

A Gemma 4 base, fine-tuned on vetted data with an exact repository commit and data-manifest hash.

  • Load the four-bit base with Unsloth FastModel; apply a Low-Rank Adaptation adapter (get_peft_model).
  • Supervised fine-tune with the gemma-4-thinking chat template and train_on_responses_only so the prompt is masked and the loss trains the reply.
  • Optimize preferences over chosen/rejected pairs so the model prefers the grounded reply to the plausible shortcut.
  • Export an optional four-bit Generative Pre-trained Transformer Generated Unified Format file for llama.cpp. LiteRT deployment is a separate conversion and validation path.

The base weights are never overwritten — the result is a small adapter beside the harness. The official Gemma 4 E2B and E4B model-variant presets use immutable model commits; custom remote models must declare their own revision. A CPU-safe validation path checks the data and plan anywhere; a future GPU run is a separate, explicit Kaggle action.

05 · The four-arm result

Promote what generalises, not what scores.

Each trained checkpoint is graded by the same self-family-excluded 0–100 judge panel as the benchmark, in all four arms, on the same prompts.

The selection rule is deliberate: we promote the variant with the smallest held-out generalisation gap and no over-refusal regression — never the one with the highest training-set score. A checkpoint that aced the training typologies but stumbles on held-out ones has memorised, not learned, and is rejected.
Honest framing. We do not claim training fully replaces the harness. The harness’s retrieval and tools supply facts the weights cannot memorise without going stale, so we expect — and report — a residual harness lift on the trained model (arm D > C). And the standing limitation is the same as the benchmark’s: the judges are language models, not anti-trafficking professionals. A blinded human-expert validation is the precondition for any peer-reviewed claim.
