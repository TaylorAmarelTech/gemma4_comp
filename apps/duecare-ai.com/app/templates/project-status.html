02 · Automation and human evidence

Prepared workflows are not recorded human participation.

The repository separates deployable containers, host-scheduled research daemons, curator-managed outreach, automated model grading, and independent human review. None is evidence that another one occurred.

Runtime · deployable

Containers serve software, not autonomous outreach

The DueCare runtime and public hub have container definitions. Hermes, the server-automation vetter, the orchestrator, and the autonomous engine are separate host-scheduled processes, currently disabled. Hermes stages synthetic research proposals under ignored reports; it does not email people or collect ratings.

Outreach · human-gated

The hub plans; a curator contacts

The outreach page detects gaps, suggests public support organizations, matches opted-in topic profiles, drafts campaigns, and vets manually forwarded observations. Because the hub retains only address hashes, it cannot send. SMTP/IMAP and Hermes mail adapters remain a reference design, not a deployed agent.

Validation · missing

364 review items, zero human ratings

The privacy-safe packet covers 364 items across 182 strata, but no qualified independent ratings, agreement statistic, or civil-society study result exists. Deterministic scores and LLM-judge scores are automated evidence and must never be relabeled as human input.

03 · Reusable architecture and evaluation

One domain implementation, a reusable capability-gap pattern.

DueCare now documents how the same separation of evidence, harnesses, deterministic checks, contextual model judges, governed agents, human review, and public sharing can be rebuilt for another industry or LLM capability gap. The generic architecture does not make trafficking-specific rules portable by assumption; every new vertical still needs its own sources, rubric, privacy policy, controls, and qualified reviewers.

Architecture · reusable

From gap discovery to maintained network

The capability-gap blueprint maps seven separate planes: claims, evidence, runtime harness, evaluation, human governance, network/publication, and agent operations. It includes a domain-pack contract, maturity ladder, container-friendly topology, promotion boundary, and replica acceptance checklist.

Evaluation · frozen

Kimi K3 plus two kinds of judging

The 500-item campaign is hash-bound and category-balanced. Each successful Kimi K3 answer receives a local deterministic grade, one independent Gemini 3.1 Pro judgment with the DueCare GREP/RAG/tool context, and one separately labelled Kimi K3 contextual self-judgment. The independent and self-family results can be compared, but never merged into a claim of human validation.

Execution · blocked

1,500 calls planned; zero results invented

The full directional topology is 500 candidate calls plus 500 Gemini judgments and 500 Kimi self-judgments. Its pre-answer worst-case reservation is 7,296,582 input tokens, 1,152,000 output tokens, and US$34.448916 at rates checked on 2026-07-28. It has not run: Kimi returned HTTP 402 for empty extra usage, and no Gemini credential is present.

Agent names do not change promotion authority.Hermes currently stages propose-only synthetic research prompts. Server automation routes and vets proposals. The Public Information Research Monitor accepts public-source update proposals. None contacts civil-society members, collects ratings, or promotes its own output; outreach remains draft-only and curator-controlled.

04 · Public deployment ownership

One source, with a distinct owner for each public surface.

Render production, the backend-free continuity copy, and the documentation are intentionally deployed by different systems. The source workflow builds portable artifacts but never overwrites either Pages deployment.

Production website

duecare-ai.com

The FastAPI hub in apps/duecare-ai.com deploys from master on Render. It serves product pages, public coordination APIs, sanitized proposal intake, and health endpoints. It does not load Gemma.

Read-only continuity

duecare-ai-site

A separate GitHub Pages repository publishes all 51 public routes plus five allowlisted snapshots. Mutable APIs and controls are disabled, its manifest records source_revision, and it has no production CNAME.

Documentation

gemma4_comp Pages

The MkDocs site deploys through docs-deploy.yml. The source-only duecare-site-build.yml uploads website artifacts for the continuity repository but never calls the Pages deploy action here.

Post-competition decision: pages plus independently governed nodes.Render and the centralized hub stay available through competition grading. After grading is owner-confirmed complete and the cutover gate passes, GitHub Pages becomes the durable public presentation. Static hosting will not provide mutable hub APIs, submissions, accounts, admin state, or automation. Organizations can still run the FastAPI hub and DueCare runtime as local or partner-owned nodes.
