01 · What is ready

Release-ready and research-incomplete are kept separate.

A green core gate means the public repository is coherent at the checked revision. It does not silently turn an unfinished dataset, adapter, or experimental judge lane into a completed scientific claim.

Stable

Core public surface

Public messaging, source-checkout smoke, manifest-backed dataset counts, model-fallback registry, provider-budget coverage, active Kaggle kernels, generated page sources, the validated deferred-work register, package-release ownership, and package-test collection pass without a model or network call.

Preserved

Dated benchmark evidence

Existing results retain their original model, prompt set, rubric, judge, and date. They are benchmark response-quality evidence, not field-effectiveness, victim-identification, or production-reliability claims.

Cost-stopped

Model and flywheel work

All five recurring tasks are disabled, four daemon sentinels are present, and zero verified repository daemons remain. Zero-call mode blocks rich-harness planning and primary-router HTTP attempts. Restarting any model caller requires reviewed pricing, finite attempt/token/cash caps, preflight, and explicit authorization.

Operational correction, 2026-07-27.A live audit found auxiliary discovery and server-automation callers still active after the main engine was paused. No local budget ledger covered that background period, so this project does not claim its historical provider usage was zero; account-side reconciliation remains private owner work. The whole stack is now stopped and its launch controls fail closed.
The strict training lane is not ready.Five dense generic-corridor typologies require a metadata-only 25-task, 75-slot curation expansion. All 75 content slots are honestly unfilled, and all 12 official-source candidates remain training-blocked pending rights review and immutable snapshots. Quality and provenance stay red until independently adjudicated rows, fingerprints, and a verified model card are regenerated through the normal append-only path.
02 · Public deployment ownership

One source, with a distinct owner for each public surface.

Render production, the backend-free continuity copy, and the documentation are intentionally deployed by different systems. The source workflow builds portable artifacts but never overwrites either Pages deployment.

Production website

duecare-ai.com

The FastAPI hub in apps/duecare-ai.com deploys from master on Render. It serves product pages, public coordination APIs, sanitized proposal intake, and health endpoints. It does not load Gemma.

Read-only continuity

duecare-ai-site

A separate GitHub Pages repository publishes all 51 public routes plus five allowlisted snapshots. Mutable APIs and controls are disabled, its manifest records source_revision, and it has no production CNAME.

Documentation

gemma4_comp Pages

The MkDocs site deploys through docs-deploy.yml. The source-only duecare-site-build.yml uploads website artifacts for the continuity repository but never calls the Pages deploy action here.

04 · What remains

The next work is explicit, bounded, and optional by lane.

The generated deferred-work register is authoritative. It rejects empty fields and unresolved tokens, and separates model-free maintenance from private, human-review, owner-decision, and budget-gated work.

P0 · Release

Freeze an approved tag

  • All 18 distributions build as wheels and source archives and clean-install as one cohort, but remain unpublished on PyPI.
  • Independent per-package semantic versions and exact tag syntax are frozen in one manifest.
  • An owner still chooses the first release package and reruns core/handoff gates on that exact revision.
P1 · Data

Close the curation queue

  • Approve lawful, immutable source snapshots and record compatible rights.
  • Fill and independently adjudicate the exact 75 risk, benign-neighbour, and corridor-counterfactual slots.
  • Regenerate quality and provenance sequentially; do not fabricate approvals.
P2 · Providers

Extend the completed ledger

  • Migrate standalone, application, and package clients one at a time with zero-transport tests.
