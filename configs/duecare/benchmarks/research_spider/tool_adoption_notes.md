Adopt or prototype first:

- `manual_dork_queue` (search_provider): Best default fallback for source discovery when credentials or network are unavailable.
- `brave_search_api` (search_provider): Good optional API candidate for public-source discovery; never send private case terms.
- `github_search_api` (tool_discovery): Best source for discovering and refreshing public Python repo candidates.
- `scrapy` (crawler): Strong candidate for polite, resumable public-source crawling if dependency cost is acceptable.
- `advertools` (crawler): Useful for sitemap-first public source expansion and JSONL crawl outputs.
- `trafilatura` (html_extractor): Best first optional extractor for public HTML text and metadata.
- `courlan` (url_filter): Good candidate for dedupe, filtering, and URL canonicalization after source discovery.
- `pdfplumber` (document_extractor): Good first PDF/table extractor candidate for public reports and court PDFs.
- `pypdf` (document_extractor): Good lightweight fallback for simple public PDF text extraction.
- `warcio` (archive_reproducibility): Good candidate for reproducible public-source snapshots with strict redaction gates.

Deferred until a concrete need or review exists:

- `searxng`: Use only after AGPL/service-boundary and instance privacy review.
- `serpapi`: Needs API key and budget decision before use.
- `ddgs`: Prefer official APIs or manual queues until reliability is proven.
- `crawlee_python`: Overlap with simpler crawler options; evaluate after a concrete need appears.

- `unstructured`: Large dependency surface; use only if lighter extractors fail.

- `theharvester`: People, email, and domain reconnaissance are out of scope.
- `metagoofil`: Metadata harvesting can expose people and internal paths.
