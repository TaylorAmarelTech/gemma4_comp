Sync Knowledge Packs

Trust boundary: This tab makes an outbound HTTPS GET to the DueCare hub (currently gemma4-comp.onrender.com, moving to duecare-ai.com when the domain is wired). Only public, pre-anonymized knowledge object envelopes are downloaded. Nothing on this kernel is sent to the hub by Sync.

One click to fetch the latest vetted (and optionally unvetted) knowledge from the live hub, unpack into /kaggle/working/knowledge/<type>/, and refresh the runtime matching-knowledge lists so the next prompt uses the new rules. Sister to the manual Import on Knowledge Extraction.

Manual upload (offline / air-gapped / private bundles)

Have a knowledge bundle ZIP from somewhere other than the public hub, such as a colleague's export, an NGO-vetted set, a sample from this page. Import it directly via POST /api/knowledge/import. The ZIP must contain entries pathed <type>/<id>.json; each envelope is validated (schema_version, knowledge_object_type, kebab-case id, content) before write. Same hot-reload behaviour as the hub sync: imported envelopes apply globally to every page on the next prompt.

Civil society vetting loop

Sync is a pull operation. It downloads only knowledge envelopes that already exist on the hub. New facts travel the other direction through Anonymization & Sharing: the local kernel strips private identifiers, the hub rejects raw PII, civil-society or curator reviewers inspect the proposal, evaluation runs against the changed pack, and clients pull the next version here.
