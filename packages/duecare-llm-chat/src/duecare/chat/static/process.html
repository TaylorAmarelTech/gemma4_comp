Bulk File Review

LOCAL NO REMOTE CALLS REVIEWER GATED Rows stay in /kaggle/working/process-staging/ until you explicitly export or share.

Drop a ZIP, CSV, JSONL, Office document, PDF, image, email, or text bundle of case material: chat exports, scans, recruitment ads, court excerpts, recorded testimony transcripts, and document photos. Each row goes through the process harness: GREP, entity extraction, document typing, person linking, hierarchy construction, and a local deterministic case brief. Optional Gemma 4 passes are explicit follow-up jobs for typed-edge proposals, graph synthesis, and privacy-safe review, so the upload path stays fast for recording. When available, a fine-tuned Gemma 4 adapter trained on reviewed document-classification and graph-edge examples can improve page-item routing, edge typing, and bulk file edge generation quality.

What this workflow does

This page is a local document-review workbench. Upload a case folder, let the process harness parse and link the evidence, review the extracted intelligence, confirm it, then ask focused investigative questions or export the bundle for the appendix notebooks.

Processing configuration

Default: Standard review. Deterministic extraction runs first; Gemma 4 is budgeted for high-signal page items and knowledge candidates.
recommended default selected
Where Gemma 4 runs on this page:
  1. During upload (Step 2) — inline Gemma 4 reads up to N page items (N = Max Gemma calls). Writes per-row case briefs and typed edges. Only fires when "Run Gemma text brief/edge synthesis inside the upload job" is checked.
  2. Explicit edge pass (Step 3) — click "Run local Gemma edge pass" after review. Gemma reviews the consolidated graph and proposes NEW edges between entities the rules missed.
  3. Graph chat (Step 4) — ask questions against the confirmed case graph. Each answer is a Gemma call.
Standard review enables path 1 with a 5-call cap so the demo finishes fast. Quick triage skips path 1 entirely.
Model fit: Deterministic extraction works without Gemma. Smaller text models are best for text-grounded edge proposals and graph chat. OCR quality depends on local OCR, and image/audio/video edge extraction requires local preprocessing plus a multimodal-capable model/runtime.
