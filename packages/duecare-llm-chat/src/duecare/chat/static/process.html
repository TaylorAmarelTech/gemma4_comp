Bulk File Review

Trust boundary: Uploaded rows are processed locally in the kernel (/kaggle/working/process-staging/). The harness runs in-process; no row is sent to any remote service. Outputs stay in the kernel until you explicitly Anonymize + Submit.

Drop a ZIP, CSV, JSONL, Office document, PDF, image, email, or text bundle of case material: chat exports, scans, recruitment ads, court excerpts, recorded testimony transcripts, and document photos. Each row goes through the process harness: GREP, entity extraction, document typing, person linking, hierarchy construction, and a compact Gemma 4 case-brief pass when a model is loaded. The page renders the extracted intelligence so you can inspect the graph before asking Gemma 4 questions about it. When available, a fine-tuned Gemma 4 adapter trained on reviewed document-classification and graph-edge examples can improve page-item routing, edge typing, and bulk file edge generation quality.

What this workflow does

This page is a local document-review workbench. Upload a case folder, let the process harness parse and link the evidence, review the extracted intelligence, confirm it, then ask focused investigative questions or export the bundle for the appendix notebooks.

Local only by defaultNo cloud API calls are required. Rows, media queue, graph edges, and notes stay in the Kaggle kernel until you explicitly export or share.
Deterministic plus GemmaParsing, GREP, entity extraction, folder edges, and journey mapping run deterministically. Local Gemma 4 can add typed edge and RAG candidates when loaded.
Fine-tuned model readyA fine-tuned Gemma 4 adapter can be used for document classification, page-item routing, and graph-edge generation while preserving the local review gate.
Reviewer controlledStep 3 is a review gate. Confirm extracted intelligence before graph questions or downstream export.
Evidence orientedEvery answer should point back to row IDs, folders, files, people, payments, dates, or queued media work.
