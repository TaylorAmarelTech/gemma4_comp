Knowledge Extraction

Trust boundary: Extraction runs locally against the loaded Gemma 4 model. Drafted envelopes stay in /kaggle/working/knowledge/; nothing leaves the kernel unless you anonymize and submit on Anonymization & Sharing.

Paste raw text from a recruiter message, case note, statute, report, or contract. The extraction harness anonymizes it, scans it against existing GREP/RAG knowledge, asks Gemma 4 to draft useful knowledge objects, and shows suggested envelopes for review. Advanced users can still choose a specific leaf type or manually author any taxonomy leaf.

Extraction harness path

Step 1
Raw text
Paste or sample a passage worth preserving. The normal path does not require choosing a schema first.
Step 2
Optional anonymize
Email, phone, and passport-like tokens are stripped before Gemma. Keep this on for case notes and user-submitted text.
Step 3
Infer types
The harness suggests useful leaves such as grep_rule, rag_doc, fact_template, context_snippet, ngo_directory, or rubric_dimension.
Step 4
Gemma 4 draft
Gemma drafts reviewable envelopes with local grounding. If no model is loaded, deterministic drafts keep the flow testable.
Step 5
Promote or submit
Save reviewed envelopes locally, export them, or send only anonymized knowledge to the hub.

Try the sample envelopes (round-trip the import flow)

Two pre-built artefacts let you confirm the import path works end-to-end. The single envelope is a plain JSON file you can open in a text editor; the bundle is a ZIP of four envelopes (grep_rule + rag_doc + context_snippet + rubric_dimension) pathed as <type>/<id>.json so /api/knowledge/import accepts it directly.
