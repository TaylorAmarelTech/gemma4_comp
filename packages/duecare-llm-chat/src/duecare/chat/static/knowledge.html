Knowledge Extraction

LOCAL NO REMOTE CALLS REVIEWER GATED Drafted envelopes stay in /kaggle/working/knowledge/ until you anonymize and submit on Anonymization & Sharing.

Upload source bundles or evidence files containing recruiter messages, case notes, statutes, reports, PDFs, images, or contracts. The page first runs the same local Bulk File Review harness used on Process: upload staging, parsing, GREP, entity extraction, folder edges, document classification, media queue, journey stages, and deterministic graph summary. The extraction harness then uses that reviewed bundle to draft standardized knowledge objects. Advanced users can still paste a short text excerpt or manually author any taxonomy leaf. Existing knowledge-object ZIPs are called knowledge files and belong in the import/export step.

What this workflow does

This page turns reviewed source bundles and public-source evidence into maintainable knowledge objects. The normal path is add source, draft suggestions, promote useful envelopes, then finish by exporting knowledge files or sharing through the redaction flow.

No schema up frontGemma 4 and deterministic hints suggest useful object types automatically.

Where Gemma 4 runs on this page:
  1. Source bundle processing — deterministic extraction by default. Gemma settings from Bulk File Review do not apply here; this page summarizes the bundle locally before drafting.
  2. Knowledge draft (Step 2) — with "Use Gemma refinement" checked, the loaded Gemma 4 model refines the envelope JSON. Without it, drafts are deterministic templates.
Gemma calls can take 1-15 minutes on Kaggle T4; the activity log emits heartbeats while a draft is running.

How drafting works (click to expand)
Draft prompt path: source bundle or text -> local Process summary and deterministic hints -> auto leaf suggestion -> fast envelope draft by default -> optional Gemma JSON refinement when enabled -> reviewer promotion -> reusable knowledge files. Imported/promoted knowledge files can later guide the Process graph/RAG prompt tree, but they are never treated as automatic truth.
Model fit: if only a small text Gemma model is loaded, keep drafts compact and expect more reviewer validation. Contact details, current legal facts, and media-derived claims should stay needs_review until verified through source documents or a stronger local preprocessing/model path.
