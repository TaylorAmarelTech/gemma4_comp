Workbench use cases

Six ways to test DueCare with Gemma 4.

These are the same audience lanes used in the public project story and video pitch. Each page gives sample prompts, the expected harness path, and links into the working UI so judges can test the actual runtime.

Audience lanes

01 Platform safety
Screen exploitative user-generated recruitment content at scale.
02 For NGOs & regulators
Speed up case analysis, triage, complaint drafts, and evidence review.
03 Individual worker / mobile
Plain-language corridor answers while keeping sensitive facts local.
04 Researcher
Version-pinned packs, reproducible runs, and citeable model behavior.
05 Anonymized knowledge sharing
Convert reviewed local evidence into redacted fact objects, evidence edges, and aggregate signals.
06 Developer / integration partner
Embed the runtime into bots, moderator consoles, case systems, or on-prem deployments.

Deployment pattern

Local first
Worker, NGO, and researcher data stays in the local kernel or tenant device unless a user deliberately exports or submits a sanitized object.
Enterprise screening
Platforms and regulators can run the same harness contracts inside moderation queues, on-prem servers, or private review tools.
Networked knowledge
The hub distributes vetted packs and receives anonymized signals or public-source proposals after local redaction and human review.

Quantitative proof path

A/B Harness Comparison
Run one prompt through no-harness and harnessed configurations, then grade both.
Bulk File Review
Process the PH to HK synthetic case bundle and inspect the extracted graph.
Standalone Grading
Use rule-based, LLM-based, and combined grading on saved responses.
Harness Contracts
Inspect which routes, layers, inputs, outputs, and model calls each harness owns.
Ecosystem Map
Show how runtime harnesses, evaluation, synthetic data, training, and deployment targets connect.
